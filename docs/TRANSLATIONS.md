# Translations

4Stim's own text (the picker, the HUD's labels, notifications, the MCM page, its HUD options) is in `Data\Interface\Translations\4Stim_en.txt`, in Fallout 4's format: UTF-16 with a byte order mark, one `$key<tab>text` line each. To translate it, copy the file as `4Stim_<language>.txt`, with the game's language code (its `sLanguage`: `de`, `fr`, `es`, `it`, `pl`, `ptbr`, `ru`, `ja`, `cn`...), and translate the texts after the tabs. Keep each `{}` (a name or number goes there, in that order; `{:.0f}` is a number without decimals).

4Stim reads the English file and then the game language's over it, so a translation can leave texts out. 4Stim also hands the file to the game's own translator when the game starts, which is how the MCM's labels are translated: the game itself only reads `<plugin>_<language>.txt` for a plugin of that name, and there's no `4Stim.esp`. The game gets one file, the language's or else the English, so a translation for the MCM should have every text (`tools/make-translations.py` writes them all). Translations are read again with `FourStim.ReloadScenes()`.

## Scene packs' text (OStim's)

Scene names, navigation labels, and furniture, voice set, light and equip object names come from the packs' files, as in OStim. A name or label starting with `$` is a key, translated the way OStim's `LocaleManager` does it (OStim NG `Game/LocaleManager.cpp`): 4Stim reads every `Data\Interface\Translations\*_<language>.txt`, with the English ones under it for keys a language doesn't have, and uses the text for the key. A key's `{...}` contents aren't part of the key: they're translated themselves and go in the text's `{}`. OStim's navigations do this for actor names: the scene says `"description": "$ostim_nav_lie_on_t{1}"`, `ONav_ENGLISH.txt` has `$ostim_nav_lie_on_t{}<tab>lie on {{}}`, which makes `lie on {1}`, and the HUD puts actor 1's name in the `{1}`: "Lie on Samantha". A scene with no `name` is named by the key `$<scene ID>` (OStim's `OScenes_ENGLISH.txt`), else by its ID.

The language in the file name is Fallout 4's (`_en`, `_de`...) or, for packs converted from Skyrim, Skyrim's (`_ENGLISH`, `_GERMAN`, `_FRENCH`, `_SPANISH`, `_ITALIAN`, `_POLISH`, `_RUSSIAN`, `_JAPANESE`, `_CHINESE`). OStim reads only the game's own name for its language; reading both is 4Stim's, so OStim packs' files work as they come. 4Stim comes with OStim's own `ONav_ENGLISH.txt` (navigation labels) and `OScenes_ENGLISH.txt` (its base scenes' names), unchanged from OStim NG, since packs made for OStim (the Lovemaking Compendium...) use OStim's keys without shipping them. These are read again with `FourStim.ReloadScenes()`; the log says how many: `Translations: <n> scene text(s) in English, <n> in "<language>", from <n> file(s)`.

## Keys

4Stim's keys are OStim's style, lowercase with underscores, and where OStim has the same text, OStim's own key with "4stim" for "ostim": the MCM's (`$4stim_page_general`, `$4stim_reset_position`, `$4stim_tooltip_fades`; MCM.md), so a translation of OStim's `OStim_<LANGUAGE>.txt` can be carried over by changing `$ostim_` to `$4stim_` (keys OStim has and 4Stim doesn't use do no harm). 4Stim's own texts are `$4stim_<words>` (`$4stim_tab_search`, `$4stim_end_scene`). The file is `4Stim_<language>.txt` with Fallout 4's language codes, not OStim's `OStim_ENGLISH.txt`: Fallout 4 names its translation files that way. (In earlier builds, 4Stim's keys were `$4Stim_CamelCase`, and the MCM's `$4Stim_MCM_<setting>`; a translation made for those needs its keys renamed.)

For authors: `tools/make-translations.py` writes `4Stim_en.txt` from the plugin's `TR("$4stim_key", "English")` / `TRF(...)` calls, the movies' `Strings.t("$4stim_key", "English")`, the MCM page (`tools/make-mcm.py`) and the options files' `"english"`.
